# 🧩 部品の決まり

見本は `samples/ui-kit.html`。部品は各アプリの `apps/web/src/components/` に同じ名前・同じ形で置く。

## 🔘 Button

送信しないボタン。`type="button"` に固定し、フォームの送信には使わない（送信は SubmitButton）。

| 種類（`variant`） | 見た目 | 使いどころ |
|---|---|---|
| `primary` | アクセント（濃）の背景 + `on-accent-strong` の文字 | その画面で一番の操作（保存・作成）。1 か所に 1 つ |
| `secondary`（既定） | ベースの背景 + アクセントの枠 | 並べる操作、キャンセル |
| `ghost` | 背景なし + アクセント（濃）の文字。なぞるとサーフェス | 行の中の操作、補助の操作 |
| `danger` | 危険の背景 + `on-danger` の文字 | 削除など取り消しにくい操作の確定 |

| 大きさ（`size`） | 高さ | 余白 | 文字 |
|---|---|---|---|
| `normal`（既定） | 40px 以上 | 8px 16px | 14px |
| `small` | 32px 以上 | 4px 12px | 13px |

- 角は 8px、アイコンと文字の間は 6px。`block` で横いっぱい
- 押せないときは `opacity: 0.55` と `cursor: not-allowed`
- 文言は折り返さない。幅が足りなければボタンの並びを次の行に回す
- アイコンだけのボタンには必ず `aria-label` を付ける
- ダイアログの中で取り消しにくい操作（ゴミ箱に移すなど）は、ほかのボタンと離して左端に置く

## 📨 Form と SubmitButton（二重送信の防止）

- 送信は必ず `Form` と `SubmitButton` で行う。生の `<form>`、`type="submit"`、React Aria の `Form` は lint で禁止する（`docs/coding.md`）
- `Form` の `onSubmit` は `FormData` を受け取る `async` 関数。終わるまで次の送信を受け付けない
- 押された瞬間に同期的に止める印（`useRef`）を持つ。状態（`useState`）の更新は画面への反映が遅れ、連打の 2 回目をすり抜けるため
- 送信中は `SubmitButton` が押せなくなり、文字の前にスピナー（14px、線 2px、`prefers-reduced-motion` で止める）を出す。`aria-busy` も付ける
- 失敗は `onError` で受けて利用者に知らせる。渡さなければ `reportError` に送る
- **サーバー側で防ぐのが本筋**。作成は `Idempotency-Key` で同じ要求を 2 回受けても 1 件しか作らない、保存は内容のハッシュで冪等にする、重い処理は利用者 × 対象の単位で 1 つずつ実行する。画面側の対策は補助
- 送信する操作を足したら、E2E に「連打しても 1 件しか作られない」確認を入れる

## ✏️ TextField

React Aria の `TextField` でラベル・説明・エラーを入力欄と結び付ける（読み上げで何の欄か分かる）。

- ラベル 13px。入力欄は高さ 40px 以上、余白 8px 10px、角 8px、枠は `border`、背景は `base`
- フォーカス中は `accent` の輪（2px）と枠。エラーのときは枠を `danger` にし、下に 12px の赤茶の文字
- 説明（`description`）は 12px の薄い文字。長い URL などは `overflow-wrap: anywhere`
- プレースホルダーは `muted`。ラベルの代わりにしない
- 入力欄の横にボタンを並べるときは `action` に渡し、入力欄とボタンの高さを 40px でそろえる（小さいボタンを下端に寄せない）
- 複数行は同じ見た目で最小 96px、縦にだけ広げられる

## 🪟 ModalDialog

画面の上に重ねるダイアログ。React Aria の `ModalOverlay` / `Modal` / `Dialog` で作る。

- **外側のクリックでは閉じない**（`isDismissable={false}`）。ほかの画面を見ながら入力していて、うっかり外を押すと入力が消えるため。閉じるのはボタンか Esc だけ
- `onClose` を渡さないダイアログは、選択肢のボタンを押すまで閉じない（Esc も効かない）。`role="alertdialog"` にする
- **入力が長いものはダイアログにせず、ページにする**（ページなら戻る・再読み込みで状況が分かり、入力の途中で閉じる事故も起きない）
- 幅は 2 つだけ

| `size` | 幅 | 使いどころ |
|---|---|---|
| `narrow`（既定） | 440px | 確認、入力が 1〜2 項目 |
| `wide` | 880px | 本文を並べて比べるもの（差分など） |

- 見出しは 17px で、先頭に内容を表すアイコンを添える
- 背景の幕は `rgb(30 25 20 / 0.45)`、ダイアログは角 14px、枠 `border`、背景 `base`、影 `0 10px 40px rgb(0 0 0 / 0.25)`、余白 18px 20px 16px
- 中身が画面より高いときは、ダイアログの中だけをスクロールさせ、ボタンまで届くようにする（`max-height: calc(100dvh - 32px)`）。ダイアログの中にさらにスクロールする枠を作らない
- ボタンは右下に右寄せで並べる（間 8px、幅が足りなければ折り返す）
- 新しいダイアログは必ずこの部品を使う

## ✳️ Icon

- アイコンは **Lucide**（ISC。一部は Feather 由来で MIT）、線の太さ **1.5**。ライセンスで守ることは `docs/licenses.md`（最新の条件は <https://lucide.dev/license>）
- Lucide の部品を直接使わず、`Icon` を通す（大きさと線の太さをそろえる）。既定の大きさ 18px、帯や小さい行では 16px
- 飾りなので `aria-hidden="true"`。アイコンだけのボタンにはボタンの側に `aria-label`
- オンの状態（登録済みの星、再開の三角など）は `filled` で塗りつぶす
- 状態・操作・見出しなど、文字のラベルにはアイコンを添える。アイコンは文字の 1 行目と上下の中心をそろえる（数値で位置をずらさない）
- **画面に絵文字を使わない。アイコンは Lucide に統一する**（OS やフォントで絵文字の見た目が変わり、紙の落ち着いた見た目から浮くため）。例外は利用者が書いた本文や Markdown の中身だけ。lint で止める（`docs/coding.md`）

### 🔴 状態の印

期日超過・今日が期日・成功・失敗など、行や欄の状態は、Lucide のアイコンを役割の色で塗った、のっぺりとした印で出す。

| 状態 | アイコン | 色 |
|---|---|---|
| 期日超過・失敗の手前 | `Circle`（`filled`、12px） | `danger` |
| 今日が期日・注意 | `Circle`（`filled`、12px） | `warning` |
| 未着手・対象外 | `Circle`（`filled`、12px） | `muted` |
| 成功・反映済み | `CircleCheck`（16px） | `success` |
| 失敗 | `CircleX`（16px） | `danger` |

- 色だけに頼らず、必ず文言を添える（「期日超過」「2026-10-20 超過」など）。印は `aria-hidden`、文言を読み上げる
- 印と文言の間は 5px、文言も同じ役割の色にする

## 🗃️ 欄（DashboardSection）

ダッシュボードなどで、内容ごとにまとめた 1 つの枠。

- 枠 `border`、背景 `surface`、角 12px、余白 14px 16px、中の間 8px
- 見出し（16px）の横に件数のバッジ（`accent` の枠・`accent-strong` の数字・12px・太さ 600・丸）
- 右端に「3 分前に更新」（12px の薄い文字）
- 読み込み中は中身の代わりに「読み込み中…」（14px の薄い文字）
- **欄そのものの失敗**（取得できなかった）は、中身を出さずに失敗の帯だけを出す
- **更新の失敗**（前回の中身は残っている）は、中身を出したまま、上に失敗の帯を足す
- 失敗の帯: `danger` の文字・`danger-bg`・`danger-border`、左の枠だけ 4px、角 8px、先頭に `CircleAlert` のアイコン 16px、`role="alert"`
- 欄の中の行の背景は `base`（欄のサーフェスと差を付ける）

## 📋 一覧の行

- 行は枠 `border`・角 10px・余白 6px 10px・文字 14px。行どうしの間は 4px
- 左から: キー（番号など）→ 題名と補足（2 段）→ 期日・時刻など → 時間 → 操作のボタン（右寄せ）
- 題名は 1 行で省略。補足（分類・状態など）は 12px の薄い文字で 2 段目
- 時刻・時間は等幅の数字、右寄せ
- 下書きなど仮の状態の行は枠を破線にし、文字を薄くする
- 期日が今日なら `warning`、過ぎていれば `danger` の文字で太さ 600
- 同じものをまとめた行は、先頭に件数のバッジを出し、押すと下に個別の行を 24px 字下げで出す
- **スマホの幅（599px 以下）では行をカードに崩す**: 1 段目にキーと題名、2 段目に期日や時刻（右寄せ）、3 段目に操作のボタン（右寄せ）。横にはみ出させない
- 行の「…」のメニューは 32px 四方のボタンに `aria-label="その他の操作"`

## 🏷️ バッジ・チップ

| 種類 | 見た目 |
|---|---|
| 状態のバッジ（成功・注意・薄い） | 役割の色の 3 つ組、丸（999px）、12px、余白 0 9px |
| 件数のバッジ | `accent` の枠、`accent-strong` の数字、丸、12px 太さ 600 |
| 小さなタグ（分類・ラベル） | `border` の枠、`base` か `surface` の背景、丸、11px |
| タグのチップ | `border` の枠、丸、12px、最大 10em で省略。入りきらない分は「+N」 |
| 色のバッジ | その他の配色の `bg`・`border`・`text`、角 6px、先頭に選んだアイコン（12px）、無ければ 7px の丸（`docs/color.md`） |

## 🔔 メッセージの帯

| 種類 | 色 | 使いどころ |
|---|---|---|
| 失敗 | `danger` の 3 つ組 | 取得・保存・送信の失敗 |
| 注意 | `warning` の 3 つ組 | 保存は止めないが知っておいてほしいこと |
| お知らせ | `info-bg`・`info-border`、文字は `text` | 設定を促すなど |

- 左の枠だけ 4px、角 8〜10px、先頭にアイコン。文字は 13〜14px

## 🍽️ メニュー（Popover）

- 背景 `base`、枠 `border`、角 10px、影 `0 6px 20px rgb(0 0 0 / 0.15)`、余白 4px、最小の幅 160〜220px
- 項目は 14px、余白 8px 10px、角 6px、アイコンとの間 10px。フォーカス中は `surface`
- 選んでいる項目は右端にチェックのアイコン（`accent-strong`）

## ⚖️ アプリごとの違いと決めたこと（2026-10-23）

- **ダイアログを外側のクリックで閉じるか**: アプリによって閉じるものと閉じないものがあった。閉じると入力が消える事故が起きるため、**閉じない**を正にした。閉じるアプリは合わせて直すこと
- **ダイアログの幅**: 420px / 640px と 440px / 880px の 2 通りがあった。**440px / 880px** を正にした。項目の多い入力は wide のダイアログではなくページにする
- **二重送信**: サーバー側で防ぐアプリと、当面は画面側だけで防ぐアプリがあった（アプリごとの判断）。souan の決まりは**サーバー側が本筋**
- **アイコンの塗りつぶし**: `filled` は一部のアプリにだけある。souan では部品の一部として含めた
- **ダイアログの見出し**: `TitleWithIcon` を使うアプリと、`Icon` を直に並べるアプリがある。見た目は同じなので、どちらでもよい
