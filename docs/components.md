# 🧩 部品の決まり

見本は `samples/ui-kit.html`。部品は各アプリの `apps/web/src/components/` に同じ名前・同じ形で置く。

## 🔘 Button

送信しないボタン。`type="button"` に固定し、フォームの送信には使わない（送信は SubmitButton）。

| 種類（`variant`） | 見た目 | 使いどころ |
|---|---|---|
| `primary` | アクセント（濃）の背景 + `on-accent-strong` の文字 | その画面で一番の操作（保存・作成）。1 か所に 1 つ |
| `secondary`（既定） | ベースの背景 + アクセントの枠 | 並べる操作、キャンセル |
| `ghost` | 背景なし + アクセント（濃）の文字。なぞるとサーフェス | 行の中の操作、補助の操作 |
| `danger` | 危険の背景 + `on-danger` の文字 | 削除など取り消しにくい操作の確定 |

| 大きさ（`size`） | 高さ | 余白 | 文字 |
|---|---|---|---|
| `normal`（既定） | 40px 以上 | 8px 16px | 14px |
| `small` | 32px 以上 | 4px 12px | 13px |

- 角は 8px、アイコンと文字の間は 6px。`block` で横いっぱい
- 押せないときは `opacity: 0.55` と `cursor: not-allowed`
- 文言は折り返さない。幅が足りなければボタンの並びを次の行に回す
- アイコンだけのボタンには必ず `aria-label` を付ける
- ダイアログの中で取り消しにくい操作（ゴミ箱に移すなど）は、ほかのボタンと離して左端に置く

## 📨 Form と SubmitButton（二重送信の防止）

- 送信は必ず `Form` と `SubmitButton` で行う。生の `<form>`、`type="submit"`、React Aria の `Form` は lint で禁止する（`docs/coding.md`）
- `Form` の `onSubmit` は `FormData` を受け取る `async` 関数。終わるまで次の送信を受け付けない
- 押された瞬間に同期的に止める印（`useRef`）を持つ。状態（`useState`）の更新は画面への反映が遅れ、連打の 2 回目をすり抜けるため
- 送信中は `SubmitButton` が押せなくなり、文字の前にスピナー（14px、線 2px、`prefers-reduced-motion` で止める）を出す。`aria-busy` も付ける
- 失敗は `onError` で受けて利用者に知らせる。渡さなければ `reportError` に送る
- **サーバー側で防ぐのが本筋**。作成は `Idempotency-Key` で同じ要求を 2 回受けても 1 件しか作らない、保存は内容のハッシュで冪等にする、重い処理は利用者 × 対象の単位で 1 つずつ実行する。画面側の対策は補助
- 送信する操作を足したら、E2E に「連打しても 1 件しか作られない」確認を入れる

## ✏️ TextField

React Aria の `TextField` でラベル・説明・エラーを入力欄と結び付ける（読み上げで何の欄か分かる）。

- ラベル 13px。入力欄は高さ 40px 以上、余白 8px 10px、角 8px、枠は `border`、背景は `base`
- フォーカス中は `accent` の輪（2px）と枠。エラーのときは枠を `danger` にし、下に 12px の赤茶の文字
- 説明（`description`）は 12px の薄い文字。長い URL などは `overflow-wrap: anywhere`
- プレースホルダーは `muted`。ラベルの代わりにしない
- 入力欄の横にボタンを並べるときは `action` に渡し、入力欄とボタンの高さを 40px でそろえる（小さいボタンを下端に寄せない）
- 複数行は同じ見た目で最小 96px、縦にだけ広げられる

## ☑️ チェックボックス・ラジオボタン・選択肢のボタン

React Aria の `Checkbox`・`RadioGroup` と `Radio` で作る（読み上げ・矢印キーに対応する）。見た目の箱は飾りなので `aria-hidden`。

| 部品 | 使いどころ |
|---|---|
| `CheckboxField` | オンとオフ、いくつでも選べるもの |
| ラジオボタン | 1 つだけ選ぶもので、選択肢が 5 個以上か、文言が長いもの |
| `ChoiceGroup`（選択肢のボタン） | 1 つだけ選ぶもので、選択肢が 2〜4 個でアイコンで表せるもの |

- **チェックボックス**: 箱は 18px 四方、角 4px、枠 `border`、背景 `base`。選ぶと枠と中を `accent-strong` で塗り、内側に 3px の `base` の余白を残す（中に四角が見える）。文言との間 8px、文言は 14px で長ければ折り返す
- **ラジオボタン**: チェックボックスと同じ作りで、箱を丸（999px）にする。選択肢は縦に並べ、間は 8px。まとまりの見出しは 13px（`TextField` のラベルと同じ）
- **選択肢のボタン**: 等しい幅で横に並べる（間 8px）。高さ 40px 以上、余白 8px 10px、角 8px、枠 `border`、背景 `base`、先頭にアイコン 16px。選んだものは**塗らず**、枠と文字を `accent-strong` にして内側に 1px の輪を足し、文字を太くする（送信のボタンと見分けるため）。なぞると枠を `accent`
- フォーカスはキーボードで動かしたときだけ、箱（選択肢のボタンはボタン全体）に `accent` の輪 2px を 2px 離して出す
- 押せないときはチェックボックス・ラジオボタンは `opacity: 0.5`、選択肢のボタンは `0.55` と `cursor: not-allowed`
- 一覧の行ごとのチェックボックスのように、見えている文言だけで何のチェックボックスか分からないときは `aria-label` を付ける
- 丸いラジオボタンは、チェックボックスに合わせて souan で足した作り（2026-10-23 時点でアプリには無い）

## 🔁 切り替えのボタン

本文の幅など、2 つの状態を行き来する操作は、押すたびに文言とアイコンが入れ替わる `Button`（`ghost`・`small`）にする。

- 文言は「押すとどうなるか」を書く（「幅を広げる」⇔「読みやすい幅に戻す」）。アイコンも次の状態を表すものにする
- 文字は `muted` にして、主な操作より目立たせない。`title` に詳しい説明を入れる
- 切り替えても意味のない狭い画面（899px 以下など）では出さない
- オンとオフの設定を保存する欄（設定の画面など）には使わず、チェックボックスにする

## 🪟 ModalDialog

画面の上に重ねるダイアログ。React Aria の `ModalOverlay` / `Modal` / `Dialog` で作る。

- **外側のクリックでは閉じない**（`isDismissable={false}`）。ほかの画面を見ながら入力していて、うっかり外を押すと入力が消えるため。閉じるのはボタンか Esc だけ
- `onClose` を渡さないダイアログは、選択肢のボタンを押すまで閉じない（Esc も効かない）。`role="alertdialog"` にする
- **入力が長いものはダイアログにせず、ページにする**（ページなら戻る・再読み込みで状況が分かり、入力の途中で閉じる事故も起きない）
- 幅は 2 つだけ

| `size` | 幅 | 使いどころ |
|---|---|---|
| `narrow`（既定） | 440px | 確認、入力が 1〜2 項目 |
| `wide` | 880px | 本文を並べて比べるもの（差分など） |

- 見出しは 17px で、先頭に内容を表すアイコンを添える
- 背景の幕は `rgb(30 25 20 / 0.45)`、ダイアログは角 14px、枠 `border`、背景 `base`、影 `0 10px 40px rgb(0 0 0 / 0.25)`、余白 18px 20px 16px
- 中身が画面より高いときは、ダイアログの中だけをスクロールさせ、ボタンまで届くようにする（`max-height: calc(100dvh - 32px)`）。ダイアログの中にさらにスクロールする枠を作らない
- ボタンは右下に右寄せで並べる（間 8px、幅が足りなければ折り返す）
- 新しいダイアログは必ずこの部品を使う

## ✳️ Icon

- アイコンは **Lucide**（ISC。一部は Feather 由来で MIT）、線の太さ **1.5**。ライセンスで守ることは `docs/licenses.md`（最新の条件は <https://lucide.dev/license>）
- Lucide の部品を直接使わず、`Icon` を通す（大きさと線の太さをそろえる）。既定の大きさ 18px、帯や小さい行では 16px
- 飾りなので `aria-hidden="true"`。アイコンだけのボタンにはボタンの側に `aria-label`
- オンの状態（登録済みの星、再開の三角など）は `filled` で塗りつぶす
- 状態・操作・見出しなど、文字のラベルにはアイコンを添える。アイコンは文字の 1 行目と上下の中心をそろえる（数値で位置をずらさない）
- **画面に絵文字を使わない。アイコンは Lucide に統一する**（OS やフォントで絵文字の見た目が変わり、紙の落ち着いた見た目から浮くため）。例外は利用者が書いた本文や Markdown の中身だけ。lint で止める（`docs/coding.md`）

### 🔴 状態の印

期日超過・今日が期日・成功・失敗など、行や欄の状態は、Lucide のアイコンを役割の色で塗った、のっぺりとした印で出す。

| 状態 | アイコン | 色 |
|---|---|---|
| 期日超過・失敗の手前 | `Circle`（`filled`、12px） | `danger` |
| 今日が期日・注意 | `Circle`（`filled`、12px） | `warning` |
| 期日がまだ先 | `Circle`（輪郭、12px） | `muted` |
| 未着手・対象外 | `Circle`（`filled`、12px） | `muted` |
| 成功・反映済み | `CircleCheck`（16px） | `success` |
| 失敗 | `CircleX`（16px） | `danger` |

- 期日の印は 3 段: 超過は塗りの `danger`、今日は塗りの `warning`、まだ先は `muted` の**輪郭の円**。まだ先を輪郭にするのは、同じ `muted` の塗りの円（未着手・対象外）と見分けるため
- 色だけに頼らず、必ず文言を添える（「期日超過」「2026-10-20 超過」「2026-11-02 まで」など）。印は `aria-hidden`、文言を読み上げる
- 印と文言の間は 5px、文言も同じ役割の色にする（分類の色の行のカードの中では文言を `text` にする。下の「分類の色の行のカード」）

## 🗃️ 欄（DashboardSection）

ダッシュボードなどで、内容ごとにまとめた 1 つの枠。

- 枠 `border`、背景 `surface`、角 12px、余白 14px 16px、中の間 8px
- 見出し（16px）の横に件数のバッジ（`accent` の枠・`accent-strong` の数字・12px・太さ 600・丸）
- 右端に「3 分前に更新」（12px の薄い文字）
- 読み込み中は中身の代わりに「読み込み中…」（14px の薄い文字）
- **欄そのものの失敗**（取得できなかった）は、中身を出さずに失敗の帯だけを出す
- **更新の失敗**（前回の中身は残っている）は、中身を出したまま、上に失敗の帯を足す
- 失敗の帯: `danger` の文字・`danger-bg`・`danger-border`、左の枠だけ 4px、角 8px、先頭に `CircleAlert` のアイコン 16px、`role="alert"`
- 欄の中の行の背景は `base`（欄のサーフェスと差を付ける）

## 📋 一覧の行

- 行は枠 `border`・角 10px・余白 6px 10px・文字 14px。行どうしの間は 4px
- 左から: キー（番号など）→ 題名と補足（2 段）→ 期日・時刻など → 時間 → 操作のボタン（右寄せ）
- 題名は 1 行で省略。補足（分類・状態など）は 12px の薄い文字で 2 段目
- 時刻・時間は等幅の数字、右寄せ
- 下書きなど仮の状態の行は枠を破線にし、文字を薄くする
- 期日が今日なら `warning`、過ぎていれば `danger` の文字で太さ 600
- 同じものをまとめた行は、先頭に件数のバッジを出し、押すと下に個別の行を 24px 字下げで出す
- **スマホの幅（599px 以下）では行をカードに崩す**: 1 段目にキーと題名、2 段目に期日や時刻（右寄せ）、3 段目に操作のボタン（右寄せ）。横にはみ出させない
- 行の「…」のメニューは 32px 四方のボタンに `aria-label="その他の操作"`

## 🧺 分類の色の行のカード

一覧の行を、分類の色で塗ったカードにする。行ごとの分類をひと目で見分けたい一覧に使う。

| 項目 | 値 |
|---|---|
| 背景 | 分類の色の `bg`（暗い見た目のときは `dark.bg`） |
| 枠 | 分類の色の `border`（暗い見た目のときは `dark.border`） |
| 色の無い行 | いつもの `surface` の背景と `border` の枠 |
| 文字 | **すべて `text`**（題名・2 段目の補足・番号のリンク・期日の文言・メニューのボタン） |
| 期日の印のアイコン | 役割の色のまま（文字ではないので 3 以上でよい。最小は `warning` の 4.02） |

- **補足の文字も `muted` にしない**。分類の色の `bg` の上では、`muted` が白紙・半紙・鳥の子・生成りの 4 つのテーマで多くの色が 4.5 を下回る（最小 3.96）。`danger`（4.40）・`warning`（4.02）・`accent-strong`（3.76）の文字も同じ。`text` は全テーマ・全色で 6.67 以上ある
- 番号のリンクは `text` の色にし、下線でリンクと分かるようにする
- 分類の名前も 2 段目に文字で書く（色だけに頼らない）。行の中に同じ色のバッジは置かない
- 行の帯（`docs/color.md`）と同時には使わない

**実装**: 分類の色のキーから CSS 変数を返す関数を 1 つ作り、行の `style` に渡す。CSS は変数が無ければいつもの色に戻す。

```ts
// 30 色のプリセットのキーだけを受け付ける。null・空・知らないキーは {} を返す（行は surface に戻る）
export function rowColorVars(key: string | null, dark: boolean): Record<string, string> {
  const color = EXTRA_COLORS.find((item) => item.key === key);
  if (color === undefined) return {};
  const tone = dark ? color.dark : color.light;
  return { "--row-bg": tone.bg, "--row-border": tone.border };
}
```

```css
.row { background: var(--row-bg, var(--color-surface)); border-color: var(--row-border, var(--color-border)); }
```

- 関数は `tokens/extra-colors.json` の 30 色のキー以外を受け付けない。保存された値をそのまま `style` に入れると、7 テーマで比を確かめていない色や、CSS として解釈される文字列が入るため
- `dark` は `docs/color.md` の「今の見た目が暗いか」の判定で決め、`data-theme` の変化と `prefers-color-scheme` の変化の両方で塗り直す

## 🔽 SelectField（セレクト）

一覧から 1 つを選ぶ欄。React Aria の `Select`・`ListBox` で作る（矢印キー・頭文字で動ける、読み上げで選んだ値が分かる）。

| 選択肢の数 | 使う部品 |
|---|---|
| 2〜4 個でアイコンで表せる | 選択肢のボタン（`ChoiceGroup`） |
| 5 個以上、または文言が長い | `SelectField`（ラジオボタンを縦に並べる場所がないとき） |
| 多くて名前で探したい | 探して選ぶ欄 |

- ラベル 13px、ラベルとボタンの間 4px。説明は 12px の薄い文字（`TextField` と同じ）
- ボタンは入力欄と同じ見た目: 高さ 40px 以上、余白 8px 10px、角 8px、枠 `border`、背景 `base`。右端に `ChevronDown`（16px、`muted`）
- 選んだ値は 1 行で省略する。列の幅を置き場所に固定する（`grid-template-columns: minmax(0, 1fr)`）。長い選択肢でボタンが広がらないようにするため
- なぞると枠を `accent`。キーボードで来たときは `accent` の輪 2px（オフセット 0）と枠
- 選択肢の箱はメニュー（Popover）と同じ見た目: 背景 `base`、枠 `border`、角 10px、影 `0 6px 20px rgb(0 0 0 / 0.15)`、余白 4px
- 箱の幅はボタンに合わせる（`--trigger-width`）。高さは 320px までで、超えたら箱の中だけをスクロール
- 項目は 14px、余白 8px 10px、角 6px。フォーカス中は `surface`。長い文言は折り返す（`overflow-wrap: anywhere`）
- 選んでいる項目は文字を `accent-strong`・太さ 600 にし、右端にチェック（`accent-strong`）
- 押せないときは `opacity: 0.55` と `cursor: not-allowed`

## 🔎 探して選ぶ欄

選ぶ対象が多く、名前で絞り込んでから選ぶ欄。押すと開くボタンと、開いたポップオーバーの中の絞り込みの欄と一覧で作る。React Aria の `DialogTrigger`・`Popover`・`Dialog`・`Autocomplete`・`SearchField`・`ListBox`・`ListBoxSection` を使う。

- **押すボタン**は `SelectField` のボタンと同じ見た目（高さ 40px）。先頭に対象を表すアイコン 16px。まだ選んでいなければ文言を `muted` にする。選んだ後は分類の色のバッジと名前を並べ、名前は 1 行で省略
- ボタンの `aria-label` には「やること: 週末の買い出しリストを作る」のように欄の名前と選んだ値を入れる
- **ポップオーバー**: 幅 `min(28rem, calc(100vw - 32px))`、余白 8px、中の間 6px。見た目はメニューと同じ（背景・枠・角 10px・影）
- **絞り込みの欄**: 枠 `border`、角 8px、余白 0 8px、先頭に `Search`（16px、`muted`）、高さ 36px、14px。フォーカス中は欄全体に `accent` の輪 2px と枠。検索欄の × は出さない（Esc で閉じるため）。開いたらここにフォーカスを置く
- **一覧**: 高さ `min(24rem, 50vh)` まで、超えたら一覧だけをスクロール
- **区分の見出し**（最近使った・すべて など）: 12px の `muted`、余白 8px 10px 2px、スクロールしても上に残す（`position: sticky`、背景 `base`）。中身の無い区分は出さない
- **項目**: メニューの項目と同じ（14px、余白 8px 10px、角 6px、フォーカス中は `surface`）。2 段にするときは 2 段目を 12px の `muted`（分類のバッジ・状態・期日）。題名は 1 行で省略
- 選んでいる項目は右端にチェック。「選ばない」の行を先頭に置くときは文字を `muted` にする
- 一覧の下に、読み込み中・見つかりません・失敗を 12px の文で出す（`aria-live="polite"`、失敗は `danger` の文字と `role="alert"`）
- 入力のたびにサーバーへ問い合わせない（300ms 待ってから送る）
- 上下キーで行を動き、Enter で選び、Esc で閉じる。選ぶと閉じてボタンにフォーカスを戻す

## 🪜 段階的に絞る選択

項目が多く、分類から選ぶほうが早い欄。見た目と部品は「探して選ぶ欄」と同じ（押すボタン・ポップオーバー・絞り込みの欄・項目）で、中身の並びが違う。

上から:

1. **固定した項目**（ピン）: 先頭に `Pin`（16px、`muted`）。下に `border` の線で区切る
2. **検索欄**: 「すべてから探す」。文字を入れると、分類に関係なくすべての項目からの結果に切り替わる（区分の見出しは「すべてから探した結果」、下に件数か「見つかりません」）。結果の間は固定した項目を隠す
3. **一覧**: 「なし（選ばない）」→「最近使った」（5 件）→「分類」。分類の行は印（7px の丸）・名前・件数（12px の `muted`）・`ChevronRight`
4. 分類を押すと、その分類の項目だけの一覧にする。先頭に「分類の一覧」の行（`ArrowLeft`、`muted`）を置き、押すと戻る

| | 探して選ぶ欄 | 段階的に絞る選択 |
|---|---|---|
| 一覧の作り | 区分（最近使った・すべて）を 1 枚に並べる | 分類の一覧 → 分類の中の 2 段 |
| 固定した項目 | なし | 検索欄の上に置く |
| 検索 | 今の一覧を絞り込む | すべての項目から探す（分類の中にいても） |
| 戻る | なし | 「分類の一覧」の行、Backspace（検索欄が空のとき）、← |
| 使いどころ | 数十件まで | 分類があり、項目が数十件を超えるもの |

**キーボード**（フォーカスは検索欄に置いたまま、`aria-activedescendant` で行を指す）

| キー | 動き |
|---|---|
| ↑ ↓ | 行を動く。端で止まる。一覧の先頭から ↑ で固定した項目に上がる |
| Enter | 項目なら選んで閉じ、分類なら開き、「分類の一覧」なら戻る |
| → | 分類の行で、検索欄が空なら開く |
| ← ・ Backspace | 分類の中で、検索欄が空なら分類の一覧に戻る（戻った分類の行を指す） |
| Esc | 閉じて押すボタンにフォーカスを戻す |
| Tab | 閉じて次へ移る（一覧にはフォーカスを入れない。`tabindex="-1"`） |

- 開いたときは、選んでいる項目が見えていればそれを、無ければ一覧の最初の項目を指す。分類を開いたときはその分類の最初の項目を指す
- 日本語の変換中のキーは変換の操作として扱い、選ぶ操作にしない
- 外側を押したら閉じる。選ぶと閉じて押すボタンにフォーカスを戻し、ボタンに分類の色のバッジと名前を出す
- 固定した項目・最近使った件数（5 件）は利用者ごとに覚える。固定するかどうかは項目のメニューで選ぶ（このポップオーバーの中では外さない）

## 📅 日付・時刻の入力

ブラウザの素の入力欄（`type="date"`・`"time"`・`"datetime-local"`）を使い、`TextField` の入力欄と同じ見た目にする。

- 見た目は入力欄そのもの（高さ 40px 以上、余白 8px 10px、角 8px、枠 `border`、背景 `base`）。ラベル・説明・エラーの付け方も `TextField` と同じ
- 数字の幅をそろえる（`font-variant-numeric: tabular-nums`）。iOS で値が中央に寄るので左寄せにする（`::-webkit-date-and-time-value { text-align: left; }`）
- Chrome は日付の欄の内側に上下 1px の余白があり、ほかの入力欄より 2px 高くなる。`::-webkit-datetime-edit-fields-wrapper { padding: 0; }` で消す
- カレンダーのアイコンの色は `color-scheme`（テーマごとに `light` / `dark`）で切り替わる。自分で塗らない
- 開始と終了のように組になるものは 2 列に並べ（間 12px）、599px 以下では 1 列にする
- 終了が開始より前などの誤りは、送信の前に確かめて欄の下にエラーを出す
- 日付を選ぶ独自の部品（カレンダーのポップオーバー）は作らない。必要になったら React Aria の `DatePicker` で作る

## 🔖 選ぶタグ（TagFilter・TagPicker）

タグはどちらも React Aria の `TagGroup` で作る（矢印キーで動き、読み上げで選んだかが分かる）。

### TagFilter（絞り込み・いくつでも選べる）

- 札は丸（999px）、高さ 32px 以上、余白 2px 12px、13px、枠 `border`、背景 `base`。先頭に `Tag` のアイコン 14px、間 4px

- 選んだ札は**塗らず**、枠と文字を `accent-strong` にして内側に 1px の輪を足し、文字を太くする（選択肢のボタンと同じ考え方）
- なぞると枠を `accent`。キーボードで来たときは `accent` の輪 2px を 2px 離して出す
- タグが 1 つも無いときは欄ごと出さない

### TagPicker（名前を付ける）

- 付けたタグは丸、高さ 32px 以上、余白 2px 3px 2px 12px、13px、枠 `accent`、文字 `accent-strong`、背景 `base`
- 右端に外すボタン: 24px の丸、`X` のアイコン 14px、`aria-label="〇〇を外す"`。なぞると `surface`。Backspace・Delete でも外せる（`TagGroup` の `onRemove`）
- 見出しは 13px、先頭に `Tags` のアイコン 14px、「タグ（5 個まで）」のように上限を書く
- 候補は小さいボタン（`small`）を丸くし、枠を `border` にする。先頭に `Plus` 14px。付けた候補は一覧から除く
- 新しい名前は `TextField` と「足す」ボタン（`action`）で足す。入力欄で Enter を押したときは外側のフォームを送らずに足す（変換中の Enter は無視する）
- 上限まで付けたら、候補と入力欄を出さない
- 付けたタグが無いときは、空の並びで間を空けない

## 🍞 トーストと画面の上の知らせ

### トースト（ToastProvider・useToast）

操作の結果を、画面の右下に重ねて知らせる。

| 種類 | 左の枠とアイコンの色 | アイコン | 役割 | 消えるまで |
|---|---|---|---|---|
| 成功 | `success` | `CircleCheck` | `role="status"` | 4 秒 |
| お知らせ | `info` | `Info` | `role="status"` | 4 秒 |
| 注意 | `warning` | `TriangleAlert` | `role="status"` | 4 秒 |
| 失敗 | `danger` | `CircleX` | `role="alert"` | 閉じるまで残す |

- 置き場所は右下（右と下から 16px）、間 8px で積む。幅は `min(360px, calc(100vw - 32px))`、640px 以下は左右 16px までいっぱい
- 1 つのトースト: 背景 `base`、枠 `border`、左の枠だけ 4px を役割の色、角 10px、余白 10px 10px 10px 14px、影 `0 6px 20px rgb(0 0 0 / 0.15)`、中の間 10px
- アイコンは 20px、題名の 1 行目にそろえる。題名は 14px で太く、補足は 13px の `muted`
- 右端に閉じるボタン（28px 四方、角 6px、`X`、`aria-label="閉じる"`、文字 `muted`、なぞると `surface`）
- 入れ物に `aria-live="polite"` を付けて常に置いておく（後から足したトーストが読み上げられるように）
- 失敗は読み落とさないよう自動では消さない。画面の中で直せる失敗（入力の誤りなど）はトーストにせず、欄の下のエラーや帯で出す

### 画面の上の知らせ

利用者の操作なしに画面を書き換えたこと（ほかの画面で変わったので読み直した、など）を伝えるだけの小さな帯。

- 画面の上の中央（ヘッダーの下、上から 64px）に 1 つだけ出す。4 秒で消す。閉じるボタンは置かず、押せない（`pointer-events: none`）
- 丸（999px）、余白 4px 12px、13px、`info` の 3 つ組（文字 `info`）、先頭にアイコン 14px（読み直しなら `RefreshCw`）、影 `0 4px 12px rgb(0 0 0 / 0.1)`
- 幅は文言に合わせ（`width: max-content`）、`calc(100vw - 32px)` を超えたら折り返す
- 入れ物は `role="status"` で常に置いておき、文言が入ったときに読み上げさせる
- 利用者の操作の結果はこれで知らせない（トーストにする）

## ⏳ Spinner

処理中を表す回る輪。ボタンの送信中・欄の読み込み中・更新中に使う。

- 14px 四方、線 2px（`currentColor`）、右側だけ透明、0.8 秒で 1 回転（`linear`）
- 色は周りの文字と同じ（`currentColor`）。主ボタンの中なら `on-accent-strong`、薄い文字の中なら `muted` になる
- 飾りなので `aria-hidden="true"`。必ず「保存中…」「読み込み中…」「更新中…」の文言と並べ、文言との間は 6px
- 処理中のボタンは押せなくし、`aria-busy="true"` を付ける。読み込み中の文は `role="status"`
- `prefers-reduced-motion: reduce` のときは回さない（止まった輪と文言で伝わる）
- 大きさは 1 つだけ。ページ全体を覆う大きな読み込みの表示は作らない（欄ごとに「読み込み中…」を出す）

## 💬 ツールチップ（title で済ませる）

- 独自のツールチップの部品は作らず、`title` 属性で済ませる
- `title` に入れるもの: 省略した題名や名前の全文、アイコンだけのボタンの補足、切り替えのボタンの詳しい説明、色やアイコンのマスの名前
- `title` は読み上げとタッチで確実には伝わらない。アイコンだけのボタンには必ず `aria-label` を付け、操作に欠かせない説明は画面に文で出す
- 文言が `aria-label` と同じなら `title` にも同じ文言でよい（ずらさない）

## 📂 開け閉めする欄（Disclosure）

本文の一部を折りたたむ欄。素の `<details>` は使わず、React Aria の `Disclosure`・`DisclosurePanel` と、`Heading` の中の `Button slot="trigger"` で作る（見出しとして読み上げられ、`aria-expanded` が付く）。

| 種類 | 見た目 | 使いどころ |
|---|---|---|
| 枠つき（既定） | 枠 `border`、角 10px、背景 `base`、頭は 14px の太さ 600 | 見出しごとの本文、前回の記録など、中身が主役のもの |
| 枠なし（`quiet`） | 枠なし、頭は 13px の `muted` | 本文の上に添える補足（詳しい情報・設定の中身など） |

- **頭（押すところ）**: 幅いっぱいのボタン、高さ 40px 以上、余白 8px 12px、左に `ChevronRight`（16px、`muted`）を置き、開くと 90 度回して下を向ける（0.15 秒。`prefers-reduced-motion` で動かさない）。アイコンと文字の間 6px
- 頭の右端に件数や日付を添えるときは 12px の `muted`、太さは普通
- **中身**: 余白 4px 12px 12px、14px。中身の最初と最後の要素の外の余白は消す
- 枠なしの版は、頭の幅を文字に合わせ（`fit-content`）、高さ 32px 以上、余白 4px 0。中身は上に 4px だけ空ける。中に表（項目名と値）を出すときは、`surface` の背景・枠 `border`・角 8px・余白 8px 12px の箱にする
- 並べるときは間 6px。見出しの深さで字下げするときは 1 段 12px
- フォーカスの輪は、枠つきは内側（`outline-offset: -2px`）、枠なしは 2px 外
- 最初に開いておくかは置き場所で決める（浅い見出しは開く、など）。開け閉めの状態は保存しない

## 📭 空の表示（EmptyState）

一覧に何も無いときの表示。2 つの大きさを使い分ける。

| 種類 | 見た目 | 使いどころ |
|---|---|---|
| ページの大きい版 | 破線 1px の枠（`border`）、角 12px、余白 28px 16px、中の間 8px、アイコン 32px | ページの主な一覧がまだ 1 件も無いとき。最初の 1 件を作るボタンを 1 つ置ける |
| 欄の中の小さい版（`.empty`） | 枠なし、余白 24px 16px、中の間 6px、アイコン 28px | 欄（DashboardSection）の中の一覧が空、絞り込み・検索の結果が 0 件 |

- どちらも中央寄せ、文字は 14px の `muted`、アイコンは `accent` の色で上に置く（`aria-hidden`）
- 文言は 1〜2 文。何が無いかと、次にできること（「〜から作れます」）を書く。絞り込みで 0 件なら、何で絞り込んだかを書く（「『大掃除』に合うものはありません」）
- ボタンは大きい版にだけ、主な操作を 1 つ（ページのほかの場所にある作成のボタンと同じもの）
- 読み込み中・失敗を空の表示で代用しない（「読み込み中…」・失敗の帯を出す）

## ⚖️ アプリごとの違いと決めたこと（2026-10-23）

- **ダイアログを外側のクリックで閉じるか**: アプリによって閉じるものと閉じないものがあった。閉じると入力が消える事故が起きるため、**閉じない**を正にした。閉じるアプリは合わせて直すこと
- **ダイアログの幅**: 420px / 640px と 440px / 880px の 2 通りがあった。**440px / 880px** を正にした。項目の多い入力は wide のダイアログではなくページにする
- **二重送信**: サーバー側で防ぐアプリと、当面は画面側だけで防ぐアプリがあった（アプリごとの判断）。souan の決まりは**サーバー側が本筋**
- **アイコンの塗りつぶし**: `filled` は一部のアプリにだけある。souan では部品の一部として含めた
- **ダイアログの見出し**: `TitleWithIcon` を使うアプリと、`Icon` を直に並べるアプリがある。見た目は同じなので、どちらでもよい
- **探して選ぶ欄のボタンの高さ**: 36px だった。入力欄・セレクトと並ぶので **40px** にそろえた。中の項目の余白（6px 8px）もメニューの項目（8px 10px）にそろえた
- **セレクトの選んだ項目**: 文字を太くするだけのアプリがあった。メニューにそろえて**右端のチェック**も出す
- **絞り込みの欄の高さ**: 探して選ぶ欄は 36px、アイコンの選び手は 34px だった。ポップオーバーの中の絞り込みの欄は **36px** にそろえた
- **付けたタグの高さ**: 外すボタン（24px）で高さが 30px になっていた。絞り込みのタグと並べてそろうよう **32px 以上**にした
- **開け閉めする欄**: アプリによって素の `<details>` の作りがばらばらだった（頭の余白 6px 10px / 8px 12px、背景 `base` / `surface`、枠の有無、文字 13px / 14px）。**React Aria の `Disclosure`** にそろえ、値はアイコンとフォーカスの輪まで決めてあった作り（頭の余白 8px 12px・14px）を元にした。高さはボタンと同じ 40px を足した
- **空の表示**: 破線の太さ（1px / 1.5px）、余白（16px / 28px / 32px）、アイコンの有無と大きさ（なし / 28px / 40px）がばらばらだった。ページの大きい版は**破線 1px・角 12px・余白 28px・アイコン 32px**、欄の中や 0 件は既存の `.empty` にした
- **画面の上の知らせ**: 1 つのアプリにだけあった。トーストとは役割が違う（操作の結果ではなく、自動で書き換えたことを知らせる）ので、部品として残した。左右の真ん中に置くと文言が折り返すことがあったので、幅を文言に合わせる（`width: max-content`）を足した
- **ツールチップ**: どのアプリも独自の部品は無く `title` だけだった。そのままを正にした
