### 🪜 ライトの段階の作り方

- 白紙から古紙へ、ベースを少しずつ暗く・黄みを強くする。サーフェスはベースより一段暗く、枠線はさらに暗くする
- テキスト `#544739` は全段で同じ。ベースが暗くなるほど比は下がるが、古紙でも 6.6 ある
- ベースが暗くなるほど「テキスト（薄）」「アクセント（濃）」「成功・注意・危険・情報の文字色」を濃くし、どの段でも比 4.5 以上を保つ
- 役割の背景（`-bg`）と枠（`-border`）も、ベースに合わせて段ごとに暗くする

### 🌙 夜更かし（ダーク）の作り方

- ベースは黒ではなく焦げ茶 `#2B2621`。サーフェスはベースより明るく（`#352F29`）して、浮いている欄を見分ける
- 文字は生成りの色 `#E8DFD2`。アクセント（濃）は明るい緑 `#A3B7B0` にし、その上に乗る文字（`on-accent-strong`）は暗くする
- 役割の色は明るく、背景（`-bg`）は暗く沈めた色にする

### 🖋️ コントラストの強いテーマの作り方

ほかのテーマが淡く感じるときのための 7 テーマ（2026-10-30 に追加）。どれも本文の比は 14 以上（白紙は 8.8）。

- **墨**: 紙の色は白紙のまま、文字を墨に近い `#2B241D` にする。枠線・アクセント・アクセント（濃）・役割の色も一段ずつ濃くする。アクセントもベースの上で 4.7 ある
- **色紙**: 文字の濃さは墨と同じくらいにし、アクセント（`#3D8A76`）と役割の色の彩度を上げる
- **漆・藍・深緑・消し炭・葡萄**: 夜更かしより暗い地に、明るい文字 `#F7F1E7` 前後を乗せる。5 つは地の色の色相だけが違い、文字・アクセント（濃）・役割の色の明るさはほぼそろえている。アクセントは全テーマでセージの緑のまま
- 役割の背景（`-bg`）と枠（`-border`）は、地の色の色相に少し寄せる

## 🏷️ 役割の色

CSS 変数は `--color-<名前>`。

| 名前 | 意味 | 使いどころ |
|---|---|---|
| `base` | ベース | 画面の背景。入力欄・ダイアログ・一覧の行の背景 |
| `surface` | サーフェス | ヘッダー・欄（パネル）・サイドバー・メニューの選択中 |
| `border` | 枠線 | 区切り線・入力欄や欄の枠 |
| `accent` | アクセント | 枠線・フォーカスの輪・件数のバッジの枠・印。文字には使わない |
| `accent-strong` | アクセント（濃） | リンク・主ボタンの背景・ghost ボタンの文字・件数の数字 |
| `on-accent-strong` | アクセント（濃）の上の文字 | 主ボタンの文字 |
| `text` | テキスト | 本文 |
| `muted` | テキスト（薄） | 補足・日時・ラベル・プレースホルダー・空のときの 1 文 |
| `success` / `-bg` / `-border` | 成功 | 保存しました、目標を超えた時間 |
| `warning` / `-bg` / `-border` | 注意 | 未保存の変更、今日が期日 |
| `danger` / `-bg` / `-border` | 危険・エラー | 失敗の帯、削除のボタン、期日を過ぎた |
| `on-danger` | 危険の上の文字 | 危険のボタンの文字 |
| `info` / `-bg` / `-border` | 情報 | お知らせの帯、ロゴの紙の枠 |

- 役割の色は `color: var(--color-danger); background: var(--color-danger-bg); border-color: var(--color-danger-border);` の 3 つを組で使う
- 帯（メッセージ）は左の枠だけ 4px にする（`border-left-width: 4px`）

### 💻 コードの色分け

Markdown のコードなど、色分けが要るアプリのために Shiki の CSS 変数（`--shiki-*`）も `themes.css` に入れている。背景はサーフェスで、文字の色は役割の色を流用し、どれも背景の上で 4.5 以上。キーワードだけは役割の色に無い藤色（ライト `#7B4570`、夜 `#D4A8C9`）を使う。コードの色分けを使わないアプリでは、この変数は無視してよい。

## 📏 コントラスト比の決まり

- 文字として使う色は、ベース・サーフェス・各役割の背景の上でコントラスト比 **4.5 以上**（WCAG AA）
- 新しい色の組み合わせを足すときは、14 テーマすべてで比を確かめる。`samples/palette.html` を開くと今のテーマの比を計算して出す
- 2026-10-30 時点の最小値（14 テーマの中でいちばん低いもの。コントラストの強い 7 テーマはどれもこの値より高い）

| 組み合わせ | 最小 |
|---|---|
| テキスト / ベース | 6.67（古紙） |
| テキスト（薄） / サーフェス | 4.62（和紙） |
| アクセント（濃） / サーフェス | 4.62（生成り・古紙） |
| 主ボタンの文字 / アクセント（濃） | 4.85（古紙） |
| 役割の文字 / 役割の背景 | 4.61（古紙） |
| テキスト / その他の配色の背景 | 6.67（白紙〜古紙）、8.70（夜更かし） |
| テキスト（薄） / その他の配色の背景 | 3.96（白紙・半紙）。文字には使わない |
| その他の配色の `onFill` / `fill` | 4.50（ライトと夜の 60 組） |

- アクセント `#859A93` はライトのテーマで 2.1〜2.9。文字には使えず、枠線・輪・印に限る（`docs/accessibility.md` の注意も見ること）

## 🖥️ OS のダークモードとの連動

- `data-theme` を付けていないときは OS の設定に合わせる。`@media (prefers-color-scheme: dark)` の中の `:root:not([data-theme])` に夜更かしと同じ値を入れている
- テーマを選ぶメニューの先頭は「OS の設定に合わせる」（`system`）にし、選ぶと `data-theme` を外す
- 「今の見た目が暗いか」は `getComputedStyle(document.documentElement).colorScheme === "dark"` で判定する。テーマごとに入れている `color-scheme` を読むので、暗いテーマを足しても直さずに済み、`data-theme` が無くて OS がダークのときも `dark` になる。その他の配色や図（Mermaid など）を切り替えるときはこの判定を使う。テーマのキーを並べて判定しないこと
- `color-scheme` もテーマごとに入れている（フォームの部品やスクロールバーがテーマに合う）

## 🌈 その他の配色（30 色）

役割の色とは別に、分類・タグ・グラフの系列など「どれに属するか」を色で見分けたいときに使う 30 色。値は `tokens/extra-colors.json`、CSS は `tokens/extra-colors.css`、見本は `samples/extra-colors.html`。

### 🧪 作り方

- OKLCH で **10 の色相 × 濃（deep）・中（mid）・淡（pale）の 3 段**
- 役割の色の色相（赤茶 30°・黄土 85°・緑 135°・セージ 173°・青灰 245°・藤 335°）を避ける。危険や成功と見間違えないため
- 色の名前は和の伝統色（小豆鼠・樺茶・常磐・藍鼠 など）。キーは `<段>-<色相の角度 3 桁>`（例: `deep-002`、`pale-226`）
- 文字（`text`）は、その色の背景（`bg`）の上でコントラスト比 4.5 以上（実際はライト 6.1 以上、夜 7.8 以上）
- 30 色のどの 2 色も、OKLab の色差 0.04 以上離す（隣り合っても見分けられる）

### 🧱 1 色の中身

| 要素 | 使いどころ |
|---|---|
| `bg` | バッジ・チップの背景 |
| `border` | バッジ・チップの枠 |
| `text` | バッジ・チップの文字 |
| `dot` | 印の丸、行の左の帯、目標に対する横棒 |
| `fill` | 塗りのマス・塗りのバッジの背景（分類の色のマスの行のカード） |
| `onFill` | `fill` の上の文字とアイコン（`#fffcf7` か `#2b2621`） |

それぞれ `light`（ライトのテーマ用）と `dark`（暗いテーマ用）の 2 組がある。`extra-colors.css` では、暗いテーマのキーを `:root:is([data-theme="yofukashi"], [data-theme="urushi"], …)` に並べて `dark` の組を当てている。暗いテーマを足したら、ここにもキーを足すこと

### 🖌️ 使い方

```html
<span class="extra-badge" data-extra-color="deep-226">
  <span class="extra-dot" aria-hidden="true"></span>暮らし
</span>
```

```css
.extra-badge {
  background: var(--extra-bg);
  border: 1px solid var(--extra-border);
  color: var(--extra-text);
}
.extra-dot { background: var(--extra-dot); }
```

- **印（dot）**: 7px の丸。名前の前に置く。飾りなので `aria-hidden="true"` にし、色だけで何かを伝えない（必ず名前と並べる）
- **バッジ**: `bg`・`border`・`text` で塗り、先頭に印。角は 6px、文字 12px、高さ 18px の行。長い名前は省略（`text-overflow: ellipsis`）し、`title` に全文を入れる
- **行の帯**: 一覧の行の左端に幅 4px の帯を `dot` の色で置く。帯の行では背景を塗らない（行の中の `muted` の補足が読みにくくなるため）
- **行のカード**: 分類の色のマスの行のカード（`docs/components.md`）では、行の左のマスだけを `fill` で塗り、文字とアイコンを `onFill` にする。カードの枠も `fill` で囲む。右の本文は塗らない（補足の `muted` や期日の役割の色の文字を、いつもの地の上で読めるようにするため）
- **色なし**: 色を選んでいないものは、枠線（`--color-border`）と薄い文字（`--color-muted`）だけのバッジにする
- **ライトと夜の切り替え**: `extra-colors.css` を読み込めば、`data-theme` と OS の設定に合わせて自動で切り替わる。JavaScript で値を入れる場合も、上の「今の見た目が暗いか」の判定で `light` と `dark` を選ぶ
### 🧷 バッジのアイコン

- バッジには色に加えて Lucide のアイコンを 1 つ選べる。選べるのは `tokens/icons.json` の **86 個**（建物・店・乗り物・お金・グラフ・書類・機械・自然・人・道具など。`key` は Lucide のアイコン名、`label` は選ぶときの名前）
- Lucide の全体を読み込まない。アプリでは一覧の key と、名前付きで import した部品の対応表を作り、テストで一覧と対応表の key が一致することを確かめる
- バッジは、色のチップの中の先頭にアイコン（12px、線 1.5、文字と同じ `text` の色）を出す。アイコンを選んでいなければ 7px の丸（`dot`）を出す
- アイコンも飾りなので `aria-hidden="true"`。名前を必ず並べる

```html
<span class="extra-badge" data-extra-color="deep-158" title="庭">
  <svg class="icon" aria-hidden="true"><!-- Lucide の leaf --></svg>庭
</span>
```

### 🧮 塗り（fill）と、その上の文字（onFill）の決め方

- `fill` は `dot` を基本にする。`onFill` は、白に近い文字 `#fffcf7`（白紙のベース）と濃い文字 `#2b2621`（夜更かしのベース）のうち、`fill` との比が高い方
- どちらの文字でも 4.5 に届かない色だけ、OKLCH の明るさ（L）を 0.001 刻みで動かし、白に近い文字で 4.5 に届くまで下げる場合と、濃い文字で 4.5 に届くまで上げる場合のうち、動かす量の少ない方を取る。彩度と色相は変えない（sRGB に収まらなければ彩度だけを下げる）
- 2026-10-24 の時点で、60 組のうち 20 組（中の段のライト 10 色、濃の段の夜 10 色）を動かした。L の差は最大 0.04 で、色相は同じまま。最小の比は 4.50
- 値を目で決めない。色を足したり `dot` を変えたりしたら、同じ手順で計算し直し、60 組すべてが 4.5 以上かを確かめる

### ⚠️ 印の色の注意

- 淡（pale）の印はライトのベースの上で比が 2 を切るものがある。印は名前と並べて使う前提なので許すが、印だけで状態を見分けさせないこと

## ⚖️ アプリごとの違いと決めたこと（2026-10-23）

- **色の値**: 各アプリの `themes.css` の `--color-*` は（取り込んだ時点の）7 テーマとも完全に一致していた。`palette.json` を持つアプリの値とも一致
- **コードの色分け**: `--shiki-*` があるアプリと無いアプリがあった。souan では入れる側にそろえた（使わないアプリは無視してよい）
- **テーマのキー**: `palette.json` で `L0`〜`L5`・`dark` と呼んでいるアプリがあった。souan は CSS と同じ `hakushi`〜`yofukashi` を正にした
- **その他の配色**: 2026-10-23 に比べた案のうち「案 B（明るめ）」を正にした。検査に使った値（コントラスト比・近い色との差）は `extra-colors.json` から除いた
